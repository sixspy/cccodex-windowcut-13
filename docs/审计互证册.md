## 1. 正确性口径：甲路径（同事务强制审计），唯一口径

全仓关键写路径只允许走甲路径：

- 业务写入（物化 / 关窗 / 入账 / 暂存 / 重开登记 / 登录会话 / 争用登记）与
  `audit_trail` 插入在**同一 SQLite 事务**内完成；
- 审计插入后必须在同一事务内**回查确认落盘**，然后才允许 `COMMIT`；
- 审计缺失或回查不见行 → 立刻 `ROLLBACK`，**业务零改**，接口拒写（500），
  并 best-effort 在新事务记一条 `audit_deviation` 标记 + 服务端日志；
- 唯一强制提交口：`audit_svc.commit_with_audit(conn, actor, action, target, payload)`，
  关键写路径禁止绕过它自行 `conn.commit()`。

**明确不选乙路径**：不建 `audit_shadow` 影子表，不做「业务先提交、失败再补偿补齐」，
禁止甲/乙混用，禁止长期双影。历史种子数据的一次性补齐（`backfill_audit_holes`，
带 `backfill=true` 标记）不是乙路径：它只发生在启动迁移、且本身留审计，运行期写路径
仍然只有甲。

## 2. 审计动作与载荷契约（互证 join 键）

| 动作 action | 触发写路径 | target | payload 必带互证键 |
|---|---|---|---|
| `materialize_ok` | 物化成功 | `window_id` 字符串 | `mat_id`（= materializations.id）、`partition`、`row_count`、`total_amount` |
| `materialize_fail_sim` | 物化模拟失败（无业务行） | `window_id` | `partition` |
| `materialize_denied` | 未关窗/不存在等拒写 | `window_id` 或锁键 | `reason` |
| `window_close` | 关窗入账 | `window_id` | `seal_token`、`generation` |
| `ingest_in_window` / `ingest_late` / `ingest_reject` | 事件入账分流 | `biz_key` | `window_id` / `window` |
| `hold_create` 等 | 暂存写 | `biz_key` | `hold_id` |
| `login` | 登录成功 | `session` | `token_sha`、`role`；同事务写 `login_sessions` |
| `login_failed` | 登录失败（不产生会话） | 尝试的用户名 | `reason` |
| `logout` | 退出 | `session` | `token_sha`；同事务把会话置 `已退出` |
| `lock_contention` | 后到者争用失败 | `lock_key` | `contention_id`（= contention_log.id）、`path`、`holder` |
| `lock_acquire` / `lock_release` | 显式锁接口 | `lock_key` | — |
| `audit_deviation` | 强制审计失败的拒写标记 | 原 action | `reason`、`path` |

规则：

1. 争用本身必须有审计：后到者只记争用、不写业务，但 `contention_log` 行与
   `lock_contention` 审计行在**同一事务**提交（`contention_id` 互证）。
2. 同一写动作两人同时触发，必须争同一把业务锁（`materialize:{wid}` /
   `window:{wid}` / `ingest:{name}` 等）；先到者持锁办事，后到者 409 且零业务改动。
3. 失败登录也留审计；登录会话落 `login_sessions` 表，库文件仍为 `data/app.db`，
   不另起库、不另起网页。

## 3. 五处同态口径

下列五处读模型必须能互相印证，任一处对不上即互证失败（`/api/audit/proof` 报 gap）：

1. **审计列表** `/api/audit`：`audit_trail` 原始流水；
2. **动作汇总** `/api/audit/actions`：按 action 计数，须与各业务台账行数对得上；
3. **物化台账** `/api/materializations`：每行 `materializations.id` 必须能在
   `materialize_ok` 审计 payload 的 `mat_id` 中找到；
4. **登录会话** `/api/sessions`：每个有效/历史会话对应一条 `login` 审计（`token_sha`），
   退出对应 `logout`；失败登录对应 `login_failed`；
5. **争用** `/api/contention`：每行 `contention_log.id` 必须能在 `lock_contention`
   审计 payload 的 `contention_id` 中找到。

互证端点 `GET /api/audit/proof` 返回各 family 的业务行数、审计行数与 gap 清单，
`aligned=true` 当且仅当四个 family 全无 gap。禁止只改审计页过滤来制造对齐假象。

## 4. 锁规则

- `try_acquire` 用 `INSERT OR IGNORE` 抢占 `window_locks` 主键再回查持锁人，
  保证并发下不会因主键冲突炸 500：输家统一走争用登记。
- 写路径在 `finally` 中释放本连接持有的锁；争用失败者本就未持锁，释放为 no-op。
- 争用登记、争用审计、409 响应三位一体；缺审计按 §1 整笔回滚。
